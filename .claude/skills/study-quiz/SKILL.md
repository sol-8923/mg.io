# 문제 출제 (study-quiz)

시험 화면과 채점 기능은 `engine/quiz-template.html`에 이미 완성돼 있다. **이 스킬은 문제 데이터(JSON)만 만든다.** HTML을 직접 작성하거나 엔진을 고치지 않는다.

## 입력
- `output/<과목>/<범위>/blueprint.json` — 시험 설계도 (내신 시험화 에이전트가 작성). **슬롯 하나 = 문항 하나.**
- `output/<과목>/<범위>/notes.md` — 핵심 정리 (출처 쪽수 포함)
- `materials/<과목>/<단원>/` — 원문 (사실 확인용)

## 출력
- `output/<과목>/<범위>/questions.json`
- `python engine/build_quiz.py output/<과목>/<범위>/questions.json` → 같은 폴더에 `quiz.html`

## 출제 원칙
1. **설계도를 그대로 따른다.** 슬롯마다 `id`, `type`, `difficulty`, `points`, `concept`, `intent`(출제 의도)를 지킨다. 설계도와 다르게 하고 싶으면 출제하지 말고 이유를 보고한다.
2. **사실은 원문에만 근거한다.** 모든 문항에 `source`(예: `"교과서 p.34"`, `"자습서 p.12 탐구"`)를 적는다. 원문에 없는 내용, 교과서와 다른 용어는 쓰지 않는다. 교과서와 자습서 설명이 다르면 교과서를 따르고 해설에 적는다.
3. **중학생 눈높이.** 발문은 짧고 분명하게. 부정 발문("옳지 않은 것은?")은 **옳지 않은** 처럼 핵심어를 강조할 수 없으니 문장으로 분명히 쓴다("옳지 않은 것을 고르시오").
4. **선택형(5지선다)**
   - 정답은 하나(복수 정답은 설계도가 요구할 때만, 발문에 "모두 고르시오"·"2개 고르시오" 명시).
   - 오답 보기는 학생이 **실제로 헷갈리는 개념**으로 만든다. 말도 안 되는 보기, 정답보다 눈에 띄게 길거나 짧은 보기를 피한다.
   - "모두 옳다 / 정답 없음" 보기는 쓰지 않는다.
   - 정답 위치를 ①~⑤에 고르게 분산한다.
   - 내신식 합답형(ㄱ, ㄴ, ㄷ 중 옳은 것)은 `passage`에 ㄱ~ㄷ을 적고 보기를 `"ㄱ, ㄴ"` 식으로 만든다.
5. **단답형**: 답이 하나로 정해지는 질문만. 띄어쓰기·대소문자·기호는 엔진이 무시하고 비교한다. 동의어·다른 표기는 `answer` 배열에 모두 넣는다(예: `["증발", "기화"]`가 교과서상 둘 다 맞을 때만).
6. **서술형**: 모범 답안 + 채점 기준(부분 점수). 채점 기준 점수 합 = 배점. 기준은 "~을 포함하여 설명함"처럼 체크 가능한 문장으로.
7. **문항끼리 답을 알려주지 않게** 한다. 한 문항의 발문·보기에 다른 문항의 정답이 드러나면 안 된다.
8. **해설**: 왜 정답인지 + 대표 오답이 왜 틀렸는지 한두 문장. 중학생이 혼자 읽고 이해할 수 있게.

## questions.json 형식

```json
{
  "meta": {
    "id": "science-g2-unit2",            // 저장 키 (영문, 범위마다 고유)
    "title": "2학년 과학 2단원 사전 시험",
    "subject": "과학",
    "grade": "중2",
    "unit": "2. 물질의 구성",
    "description": "중간고사 대비 · 교과서 p.30~55",
    "totalPoints": 100,
    "timeLimitMin": 45                    // 실전 모드 제한 시간 (없으면 생략)
  },
  "questions": [
    {
      "id": "Q01", "type": "mc", "difficulty": "하", "points": 3, "concept": "원소",
      "passage": "(선택) 제시문·자료·ㄱㄴㄷ 보기",
      "question": "다음 중 원소에 대한 설명으로 옳은 것은?",
      "choices": ["…", "…", "…", "…", "…"],
      "answer": 3,                         // 1부터 시작. 복수 정답이면 [2, 4]
      "explanation": "…",
      "source": "교과서 p.32"
    },
    { "id": "Q02", "type": "short", "difficulty": "중", "points": 4, "concept": "…",
      "question": "…", "answer": ["정답", "인정 답안"], "answerHint": "(선택) 한 단어로 쓰시오",
      "explanation": "…", "source": "…" },
    { "id": "Q03", "type": "ox", "difficulty": "하", "points": 2, "concept": "…",
      "question": "…", "answer": true, "explanation": "…", "source": "…" },
    { "id": "S01", "type": "essay", "difficulty": "상", "points": 8, "concept": "…",
      "question": "…", "answerHint": "(선택) 두 가지를 포함하여 서술하시오",
      "modelAnswer": "…",
      "rubric": [ { "criterion": "…을 포함하여 설명함", "points": 4 },
                  { "criterion": "…을 근거로 제시함", "points": 4 } ],
      "explanation": "(선택)", "source": "…" }
  ]
}
```

- `type`: `mc`(선택형) / `short`(단답형) / `ox` / `essay`(서술형)
- `difficulty`: `상` / `중` / `하`
- 문항 순서 = 시험지 순서. 설계도의 슬롯 순서를 따른다(보통 선택형 → 단답형 → 서술형).

## 빌드와 자체 점검
1. `python engine/build_quiz.py <questions.json>` 실행.
2. `✖ 오류`가 나오면 고쳐서 다시 실행. 통과할 때까지 반복한다.
3. `⚠ 경고`(정답 위치 쏠림 등)도 가능한 한 해소한다.
4. 통과하면 생성된 `quiz.html` 경로를 보고한다.

## 반려 문항 수정
검수 보고서의 지적(문항 id / 문제점 / 수정 제안)을 받으면 **지적된 문항만** 고친다. 다른 문항을 바꿔야 하면 이유를 함께 보고한다. 수정 후 반드시 다시 빌드한다.
