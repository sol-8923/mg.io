# /study 작업 절차 v2 계획서 (2026-11-17, 승인 대기)

**목표:** `/study 1학년 2학기 과학` 한 번으로 자료 정리 → 출제 → 오답풀이 → 교과 정리 슬라이드 → 검수 → 반영·배포까지 **사람 개입 없이 끝낸다.** 단, 아래 §8의 "사용자 결정이 필요한 경우"에서만 멈춘다.

**대전제 (기존 방식으로 마쳤을 때보다 떨어지지 않을 것):**
1. 문제의 **양**: 슬롯 수·변형 수·기출 전량 편입이 기존과 같거나 더 많다.
2. 문제의 **질**: 정답·사실 오류(A급) 0, 문항 결함(B급) 비율은 기존 이하.
3. **슬라이드**: 질적 품질(사실·가독성)과 커버리지(notes 핵심 개념 빠짐없음)를 확보한다.
4. **지문(문항)당 설명·오답풀이**의 구체성·정확도는 기존과 같다(보기별 해설·상세 풀이·자주 하는 오답·기억할 점·참고 자료·쪽 근거를 줄이지 않는다).

절감은 이 넷을 해치지 않는 곳에서만 한다(§4 "줄이는 것 / 줄이지 않는 것").

## 1. 기존 방식(도덕 ① 실측)과 문제점
| 구분 | 기존 | 측정 |
|---|---|---|
| 에이전트 | 170건, 토큰 약 24.7M | 검수 49%, 슬라이드 제작·줄이기 23%, 수정·B개정·감사 13%, 단원 제작 11% |
| 검수 | 단원마다 4중(형식·내용·종합·오답풀이)을 여러 라운드 | 표본 감사에서 A급 0, B급 17.5%(대부분 기계가 잡을 수 있는 종류) |
| 슬라이드 | 책 완성 뒤 일괄, 14~16장으로 만들어 11~12장으로 줄임 | 29건, 줄이기 루프 |
| 구조 | 슬라이드 HTML 한 파일 복제, 규칙 문서 분산, 진행 상태가 대화 속 | 복제 사고 1건, 정책 충돌 다수 |

핵심 진단: **검수 비용의 대부분이 기계로 잡을 수 있는 결함을 LLM이 찾는 데 쓰였다**, 슬라이드는 **분량 예산 없이 만들고 줄였다**, 파이프라인이 **재개 가능한 상태 파일 없이** 대화에 의존했다.

## 2. 새 절차 한눈에 (모식도는 별도 그림 참고)
```
S0 준비 ─▶ S1 단원 제작(병렬) ─▶ S2 기계 관문 ─▶ S3 검수(책 단위 일괄) ─▶ S4 반영·빌드 ─▶ S5 사후 점검·배포
 코디네이터   a.notes→동결        gate+커버리지      내용(Opus)           library 이동        표본 감사
 기출 전사    b.문항·해설 ┐병렬     실패는 제작자에게   해설·종합(Sonnet)    book 빌드           신고 루프 연결
 단원 구분    c.슬라이드v2┘        자동 반송(≤2회)    슬라이드(Sonnet)     STATE 갱신          과목 md·반려예방 갱신
```
모든 단계의 상태는 `drafts/<책>/STATE.json`(`engine/pipeline_state.py`)에 기록되어 중단·한도 후에도 `next`로 이어 간다.

## 6. 반송·루프 규칙
- S2 실패 → 메시지를 그대로 제작자에게 반송, 최대 2회. 그 뒤에도 실패하면 코디네이터가 원인(지침 결함인지 자료 문제인지)을 분석해 지침을 고치거나 사용자에게 올린다.
- S3 반려 → 반려 유형이 A급이면 즉시 원문 대조 후 수정(정답·id·배점 불변 확인). B급은 모아서 한 번에 수정. 같은 쟁점이 두 라운드 연속 해결되지 않으면 사용자 결정(기존 규칙 유지).
- 반복 반려 유형은 `docs/출제-반려-예방.md`·점검 코드·과목 md에 환류(S5). 환류 누락을 막기 위해 S5 체크리스트에 항목으로 둔다.
- **notes 변경 트리거:** 검수 중 notes가 수정되면 해당 단원 슬라이드를 재빌드하고 슬라이드 검수를 다시 받는다(STATE에 표시).

## 8. 사용자 결정이 필요한 경우(자동 진행 중 멈추는 곳) 와 이번 승인 요청
**실행 중 멈추는 경우:** ① 교과서·기출 판독 불가 ② 기출 정답이 교과서와 다름 ③ 같은 쟁점 2라운드 연속 미해결 ④ 단원 범위·학교 진도 불명확 ⑤ 새 정책 보류 항목(3점 부정형 소거형 등) 해당 ⑥ A급 오류가 한 단원에 반복 발생.

## 11. 슬라이드 검수 — 갤럭시탭 S10 FE 적합성 강화 기준 (사용자 지시 2026-11-17)
**기기 사양**(공개 사양 기준, 출처: [GSMArena](https://m.gsmarena.com/samsung_galaxy_tab_s10_fe-13761.php), [Samsung 지원](https://www.samsung.com/us/support/answer/ANS10005059/)): 10.9인치, 2304×1440, 화면비 **16:10**, 249ppi, 주사율 90Hz, S펜 지원. 브라우저(Chrome·삼성 인터넷)의 CSS 화면 크기(devicePixelRatio)는 공개 자료에 없어 **가로 1280×800, 세로 800×1280 CSS px로 가정**하고, 실기기에서 한 번 실측해 맞는지 확인한다.

**왜 강화 기준이 필요한가:** 슬라이드 무대는 1920×1080(16:9)이다. 16:10 태블릿 가로(1280×800)에서는 비율 차이로 위아래에 빈 띠가 생기고(무대가 0.667배로 줄어 높이 720px), 세로(800px 폭)는 폰용 카드 배치로 전환되는 경계에 걸린다. 이 기기가 학습의 주 사용 환경에 가장 가까워서 데스크톱·폰과 별도로 본다.

| # | 점검 | 기준 | 방법 |
|---|---|---|---|
| T1 | 가로 1280×800 한 화면 | 표지·모든 장이 잘림 없이 한 화면에 들어옴. 위아래 빈 띠는 허용하되 내용이 띠 위로 넘치지 않음 | 캡처 |
| T2 | 가로 실효 글자 크기 | 무대 최소 24px → 가로에서 **실효 16px 이상**(0.667배 환산). 표·그림 속 글자도 실효 14px 이상 | 캡처 + 계산 |
| T3 | 세로 800×1280 | 카드 배치로 전환되어 가로 스크롤 없음, 카드 폭이 화면을 채우고 글자 16px 이상, 그림이 화면 폭 안에 들어옴 | 캡처 |
| T4 | 터치 조작 | 이전·다음·편집 버튼 터치 영역 **44px 이상**, 스와이프로 장 넘기기, 하단 시스템 제스처 바와 컨트롤이 겹치지 않음(`safe-area`) | 코드 검토 + 캡처 |
| T5 | S펜 | 펜으로 쓸 때 장이 넘어가거나 확대되지 않음(필기 오버레이와 충돌 없음), 펜 호버·터치 구분 | 실기기 확인(첫 책 1회) |
| T6 | 브라우저 호환 | Chrome·삼성 인터넷에서 동작(최신 CSS 기능을 쓰면 대체 스타일이 있음), 한글 글꼴 CDN 실패 시 대체 글꼴 | 코드 검토 |
| T7 | 그림 가독성 | 도식·표의 글자가 가로·세로 두 방향에서 겹치거나 잘리지 않음(화살표 라벨 포함) | 캡처 |
- 캡처는 자동 스크립트(`slide_shots.py`, 구현 예정)로 4종(1920×1080 / 1280×800 / 800×1280 / 390×844)을 한 번에 만든다. 검수자는 T1~T4·T6·T7을 캡처와 코드로, T5와 가정한 화면 크기는 사용자 실기기 확인에 맡긴다.
- **반려 기준:** T1~T4 위반은 사실 오류와 같은 급(반려). T5·T6은 시범 단계에서는 참고로 기록하고 실기기 결과가 나온 뒤 기준으로 올린다. T7은 그림이 안 읽히면 반려.

## 12. 첫 적용 결과 — 영어 ①(g1s2-english, 2026-11-17) 실측
| 항목 | 합격 기준(§5) | 실측 | 판정 |
|---|---|---|---|
| 양 | 슬롯 변형 ≥2, 기출 배정 점검 | 슬롯 17+17+19, 변형 2, 문항 106개. 기출 55문항 중 단원 배정 7개(교과서 불일치로 편입은 2개) | 충족(기출은 자료 한계) |
| 질: A급 | 0건 | 검수 3단계·표본 감사에서 정답·사실 오류 **0건** | 충족 |
| 질: B급 비율 | 표본 감사 ≤10% | 3/12 = **25%**(쪽수 정밀도 1·표시 누락 2) | **미충족** → 수정 + 확산 점검(`quote_page_check`)으로 처리, 15건 → 의도적 허용 7건 |
| 설명 | 보기별 해설·detail 3문장·쪽 근거 | gate·b_scan 0, 해설 검수 통과 | 충족 |
| 슬라이드 | 커버율 ≥95%, 12장, 그림 ✖ 0, 태블릿 T1~T4·T7 | 커버율 100%·12장·그림 점검 0, 반려 후 모두 통과(컨트롤 44px, 하단 겹침, 세로 도식) | 충족 |
| 문항 커버율 | ≥85% | u5 89%, u6 54%, u7 49%(구조·메타 제외 시 약 88%) | 도구 한계로 분류 확인(미충족 아님) |
| 비용 | 약 12~13M/10단원(약 50% 절감) | 3단원에 에이전트 약 50건, 약 7M 토큰(약 2.3M/단원, 도덕 2.5M/단원) | **절감 목표 미달**(약 10%) |
**해석:** 품질 합격 기준은 B급 비율을 제외하고 충족했다. 비용은 첫 적용이라 템플릿·도구·지침 정비 비용과 u7 3라운드가 겹쳐 절감이 거의 나지 않았다. 검수 반려 대부분은 새 문항의 설계 결함(우리말 없는 영작, 한 단어 고치기의 복수 정답, 다른 슬롯 정답 노출, 쪽수 표기)이라 §11의 사전 점검과 `quote_page_check`로 다음 책에서 줄일 수 있다. 다음 책(과학 또는 10단원 규모)에서 다시 실측해 절감 여부를 판단한다.
