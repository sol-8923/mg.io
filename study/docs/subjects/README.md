## 각 파일의 구성
1. **출제 형식** — 선택형·서술형에서 이 과목이 쓰는 문항 형태와 슬롯 배분 요령
2. **지문·자료 규칙** — 무엇을 문항에 직접 넣어야 하는지(작품 인용, 표·그래프 SVG, 사료 등)와 만드는 법
3. **오답·서술형 설계** — 이 과목의 흔한 오개념, 서술형 조건 낱말·채점 구조
4. **단원 유형별 지침** — 단원 성격(문학/문법/글쓰기, 지리/일반사회 등)에 따른 요령
5. **자주 나온 반려 사유** — 검수에서 실제로 반려된 것 중 일반화할 수 있는 것(출제 전에 점검할 것)
6. **다음 단원에서 개선할 것** — 난이도 참고, 사용자 지시, 검수의 참고 사항 중 쌓아 둘 것
7. **개선 이력** — 날짜·단원·무엇을 배워 어디를 고쳤는지 한 줄씩

## 운영 방식 (품질을 계속 올리는 순환)
- **시작할 때**: `exam-designer`·`study-quiz`·검수 에이전트는 해당 과목 파일을 먼저 읽는다(파일이 없는 과목이면 이 README의 구성대로 만든다).
- **출제할 때**: 5번 '자주 나온 반려 사유'를 체크리스트로 쓰고, 6번 '다음 단원에서 개선할 것'을 실제로 반영한다.
- **단원이 통과하면**(`/study` 8단계): 그 단원의 검수 보고서와 `review/changelog.md`를 보고 ⓐ 일반화할 수 있는 반려 사유를 5번에, ⓑ 난이도 참고·참고 사항·사용자 지시 중 다음에 반영할 것을 6번에, ⓒ 7번 이력에 한 줄 추가하고 같이 커밋한다. 이미 반영해서 해결된 항목은 6번에서 5번 '해결됨' 표시나 이력으로 옮긴다.
- 과목 파일을 고쳤을 때 **이미 통과한 단원은 다시 만들지 않는다**(새 규칙은 다음 단원부터). 소급 적용이 필요하면 사용자에게 먼저 묻는다.
- 사용자가 새로 정한 기준은 날짜와 함께 해당 과목 파일(과목 공통이면 이 README와 `study-quiz`)에 즉시 적는다.
