# 요약 슬라이드 검수 기준 (문제 출제 검수와 별도)

문제 은행 검수(`docs/subjects/README.md`)와 별개로, 단원 요약 슬라이드(`library/<책>/<단원>/slides.html`) 제작 뒤에 하는 후속 검수의 기준이다. 2026-11-16 사용자와 합의한 내용을 정리했다.

## 1. 무엇을 보나
- **내용 검수(이 문서의 중심):** 슬라이드의 모든 문장·표·그림 라벨이 단원 `notes.md`에 근거하는지, 사실·수치·용어가 왜곡되지 않았는지.
- **화면(디자인) 검수:** 글자 넘침·겹침·대비·모바일·폰트·키보드/편집 모드. 디자인 개편 직후 한 번 했다. 디자인을 크게 바꿀 때만 다시 한다. 점검 항목은 2026-11-16 화면 검수의 10개 항목(잘림/대비/도식 라벨/폰트/진행표시/하단 공백/표지/단원 일관성/장식/모바일)을 쓴다.
- 슬라이드의 근거는 `notes.md`이고, `notes.md` 자체의 정확성은 문제 은행 검수에서 다룬다(여기서는 notes.md를 정답으로 둔다).

## 2. 절차
1. **기계 점검(1단계):** `python engine/slide_check.py` — 슬라이드에는 있고 notes.md에는 없는 수치·굵은 용어를 뽑는다(쪽번호 같은 오탐 있음). 결과는 에이전트 검수의 입력.
2. **에이전트 검수(2단계):** 단원별로 notes.md와 slides.html 텍스트를 슬라이드 단위로 대조해 문장마다 분류한다.
   - `근거있음` 노트에 같은 내용 / `표현변경` 뜻이 같게 풀어씀 / `근거없음` 노트에 없는 내용 / `다름` 노트와 어긋남(수치·방향·인과가 반대, 범위 확대 등).
   - **수학·과학:** 계산 결과·단위·공식·그림의 숫자와 도형 배치(각도, 좌표, 비율, 위상, 그림자 방향 등)를 직접 검산한다.
   - **사회·국어:** 고유명사·연도·지명·작품 정보·정의 범위(과장·일반화)를 본다.
   - 보고에는 `근거없음`·`다름`만 문장 원문과 함께 적고, 나머지는 건수만 적는다.
3. **판정과 조치:**
   - `다름` → 슬라이드를 notes.md에 맞게 고친다. (A급)
   - `근거없음` → ① 학습에 꼭 필요하고 교과서에 있는 내용이면 notes.md에 근거를 보강하고 유지 ② 아니면 삭제. 그림 설명용 예시 수치는 "예시"임이 보이면 허용한다. (B급)
   - `표현변경`은 뜻이 같으면 통과.
4. **재확인:** 고친 문장만 다시 대조하고, 본문 텍스트 변경 목록을 남긴다.

## 3. 규칙
- 슬라이드 제작·수정 시 notes.md에 없는 사실을 만들지 않는다. 필요한 사실은 notes.md를 먼저 보강한다.
- 검수 에이전트는 **읽기 전용**(파일을 고치지 않고 보고만). 수정은 호출한 쪽이 한다.
- 모델은 Sonnet(대조 작업). 단 수학·과학 계산·도형 검산은 Sonnet이 불확실하면 호출자가 따로 확인한다.
- **시간 제한:** 에이전트 1개당 40분. 넘기면 지금까지 본 결과만 보고하고 못 본 단원·슬라이드를 목록으로 남긴다. 전체는 2시간 안에 끝나게 병렬(약 10개)로 돌린다.
- 병렬 에이전트는 서로의 임시 파일을 지우지 않는다. 프로세스를 이름으로 종료(taskkill 등)하지 않는다. 임시 파일은 scratchpad에만 만든다(library에 두지 않는다).
- 표본이 아닌 **전수 검수**를 기본으로 한다. 이후 notes.md나 슬라이드를 고치면 그 단원만 다시 한다.

## 4. 보고 형식
`단원: 슬라이드번호 | 분류(근거없음/다름) | 슬라이드 문장 | 노트 근거 또는 부재 | 권장 조치`. 맨 끝에 단원별 총계(근거있음/표현변경/근거없음/다름 건수)와 못 본 범위.
