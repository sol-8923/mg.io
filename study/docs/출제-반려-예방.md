# 출제 반려 예방 지침 (모든 과목 공통)

> 문제를 만들 때마다 4중 검수에서 **반복해서 반려된 사유**를 모아, 만드는 단계에서 미리 막는 규칙이다. 국어·사회 8개 단원의 검수 기록(약 40회 반려)에서 뽑았다. 과목별 기준(`subjects/<과목>.md`)과 함께 읽고, 새 반려 사유가 나오면 여기와 그 과목 5번에 **같이** 추가한다.
> 자동으로 잡을 수 있는 것은 `engine/precheck_unit.py`(규칙 파일 `engine/_precheck_extra.py`)가 검사한다. **검수에 보내기 전에 반드시 `✖ 0건`을 만든다.**

## 1. 만들기 전에 정해 둘 것 (설계 단계)
1. **사실 배분표**: 설계도 `analysis`에 "어느 사실을 어느 슬롯의 정답으로 쓰는지"를 적는다. 같은 사실을 두 슬롯의 정답이나 참인 보기로 반복하지 않는다(반려 1위).
2. **자료 세트를 먼저 나눈다**: 지문·그림·표 하나를 여러 문항이 쓸 때 그 문항들끼리 정답을 알려 주지 않도록, 문항마다 필요한 부분만 넣는다.
3. 교과서·교사용·지도서의 표현이 다른 곳은 **출제하지 않고** notes 끝에 '불일치'로 기록한다(둘 다 맞는 사례로만 낼 수는 있다).
4. 정답 번호 배분표(a·b 변형 각각 ①~⑤ 3~4개, 3연속 금지)를 설계도에 적는다.

## 2. 문항을 쓸 때 (출제 단계) — 자동 점검(✖)이 있는 것
| 반려 패턴 | 막는 법 | 자동 점검 |
|---|---|---|
| 다른 슬롯의 정답·조건 낱말이 **발문·지문·보기·해설 옆 자료(refs)·그림 캡션·그림 속 글자**에 나옴 | refs·캡션에는 그 슬롯 자기 내용만. 정의 카드·사례 표에 다른 문항의 정답 문장을 넣지 않는다. 변형 a·b의 사례행도 서로 넣지 않는다 | ✖ |
| 합답에서 **정답만 3개짜리 조합**(또는 정답만 2개짜리) | 같은 크기의 오답 조합을 1~2개 더 만든다 | ✖ |
| 합답에서 **같은 기호가 5개 보기 모두에 들어감**(그 진술이 참인 것이 드러남) | 기호 위치를 섞고 거짓 진술 위치도 바꾼다 | ✖ |
| **정답이 단독 최장 보기** | 오답을 정답과 비슷한 길이·구조로. 정답을 줄이는 쪽을 먼저 | ✖(차이 3자 이상) / ⚠ |
| 정답 번호가 a·b 변형별로 쏠림(최대-최소 ≥3) 또는 3연속 | 변형별로 재배치(fixedOrder 문항은 보기 순서를 바꿔서) | ✖ |
| 발문이 '밑줄 친'을 가리키는데 지문에 표시가 없음 | 단어를 직접 지목하거나 ㉠㉡을 붙인다 | ✖ |
| 그림 속 글자가 **그림 밖으로 잘림·서로 겹침** | 여백을 넉넉히, 오른쪽 끝 라벨은 `text-anchor=end`. 이동·회전(transform)이 있는 그림은 자동 점검이 못 하니 Edge 스크린샷(창 폭 500+, 2배 확대)으로 직접 확인 | ✖(transform 없는 그림) |
| 인용문이 원문에 없음·**출처 쪽수가 인용이 실린 쪽과 다름** | 인용은 원문 그대로, 생략은 `(…)`, 쪽수는 그 문장이 실린 쪽 | ✖/⚠ |
| 단답 정답이 다른 슬롯 발문·지문에 나옴 | 정답 낱말이 다른 문항에 새지 않게 | ✖ |
| 단답 인정 답에 **지문에서 옮겨 쓴 활용형**(예: 혼란스러웠어)이 없음 | 지문에 나온 형태를 모두 인정 답에 넣는다 | 직접 확인 |
| 서술형 모범 답안이 발문 조건(문장 수)보다 김 | 모범 답안을 조건대로 | ⚠ |
| 해설 템플릿이 만든 **조사 오류**('산맥로', '원주민로', '㉡로' — 받침 뒤에 '로') | 짝짓기·합답 해설 템플릿에서 받침을 보고 '으로/로'를 고른다(㉣만 '로', 나머지 ㉠㉡㉢㉤…은 '으로') | ✖(원문자)/⚠ |
| 두 경로·두 막대 길이를 비교하는 모식도에서 **그려진 길이가 보기 진술(더 짧다/길다)과 눈으로 안 맞음** | 수치가 없는 비교 그림은 그려진 길이가 정답과 일치해야 한다(또는 가상 km 값을 표기) | 직접 확인 |
| 정답 글자((가)~(바))가 보기 순서에 따라 섞이는 문항인데 **해설·detail에 정답 글자를 고정 문구로 씀** | 해설을 만들 때 정답 글자를 변수로 받는다(보기 순서가 섞이면 고정 문구가 틀림) | ✖ |
| 모든 문항의 `source`가 같은 값(기본값 복사) | 슬롯별 근거 쪽수(설계도 사실 배분표의 쪽)로 | ✖ |
| 학생이 보는 풀이(detail·explanation·refs)에 **'지도서'·'교사용 교과서'를 근거로 적음** | 근거는 학생 교과서 쪽수로만. 교사용·지도서에만 있는 내용은 출제·정답 근거로 쓰지 않는다 | ✖ |
| 해설의 '해마다'가 그림의 값 간격과 안 맞음 | '조사한 해마다', '3년 간격' 등 자료대로 | ⚠ |

## 3. 자동 점검이 못 잡아서 직접 확인할 것 (검수자가 자주 짚는 것)
- **복수 정답**: 오답 보기가 사실은 참일 수 있는지, 발문이 '배경'인데 보기에 경과·결과가 섞이지 않았는지.
- **지문 규칙**: 특정 사례·글·자료를 묻는 문항은 그 자료를 문항에 넣었는지. 해설·detail·refs가 지문에 없는 표현·장면을 쓰지 않는지.
- **부정형 문항**의 '참인 보기 4개'가 지문·자료 안에 근거가 있는지.
- **쉬운 문항 방지**: 사례 지문에 정답 개념어가 그대로 들어가 읽기만 해도 답이 나오지 않는지, 오답이 다른 보기와 정면으로 모순되어 소거만으로 풀리지 않는지.
- 사례가 단원 안 다른 슬롯과 겹치지 않는지(같은 도시·같은 사례 반복).
- 교과서 용어 표기(띄어쓰기·'~의 구조' 등)가 교과서와 같은지. 지도서에만 있는 용어는 쓰지 않는다.
- 통계를 인용하면 캡션에 출처·연도. 직접 만든 모식 자료는 캡션에 '모식도'.
- 서술형 채점 기준의 점수 합 = 배점, 허용 표현 구체적, 조건 낱말은 다른 슬롯에 나오지 않음.

## 4. 작업 순서 (제작자)
1. notes → 설계도(사실 배분표·번호 배분표 포함) → `gen.py`로 문항 생성(단원 폴더 안에서만, 다른 단원 스크립트 실행 금지).
2. `python engine/build_library.py --check-unit drafts/<책>/<단원>` → 오류 0·경고 0.
3. `PYTHONIOENCODING=utf-8 python engine/precheck_unit.py <책> <단원> --pages a-b --src 교과서.txt "교사용 교과서.txt"` → **✖ 0건**, ⚠는 새로 쓴 사례·인용만 남게.
4. 그림이 있으면 Edge 스크린샷으로 2배 확대 확인(특히 transform이 있는 그림).
5. 이 문서의 3번을 한 번 훑고 검수로 보낸다.

## 5. 갱신 규칙
- 검수에서 새로운 종류의 반려가 나오면: ① 자동으로 잡을 수 있으면 `engine/_precheck_extra.py`에 규칙을 추가하고 ② 이 문서 2·3번에 한 줄 추가하고 ③ 그 과목 `subjects/<과목>.md` 5번에 사례를 적는다.
- 자동 점검이 **통과한 단원을 검수자가 반려**하면 점검 규칙이 빠진 것이니 규칙을 보강한다.
