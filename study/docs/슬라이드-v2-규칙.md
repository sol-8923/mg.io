# 교과 정리 슬라이드 v2 규칙 (2026-11-17, 사용자 지시: 앞으로 새 슬라이드는 별도 요청 없이 이 방식으로 만든다)

시범(과학 4단원)에서 조립 결과가 기존과 동일함을 확인한 구조(`pilot/slides-v2/README.md`)를 운영 규칙으로 확정한다. 디자인 기준(스타일·표지·모바일·최소 글자 크기 등)은 그대로 `config/slide-style-<과목>.md`와 `docs/슬라이드-검수.md`를 따르고, 이 문서는 **파일을 어떻게 나누고 조립하고 점검하는가**만 바꾼다.

## 1. 적용 범위
- **새로 만드는 모든 슬라이드는 v2**로 만든다. 한 단원을 통째로 `slides.html` 하나로 쓰지 않는다.
- 기존(v1) 슬라이드는 그대로 둔다. 그 단원을 크게 고치게 되면 v2로 옮긴다(§7). 옮기지 않은 단원은 v1 규칙(`docs/슬라이드-검수.md`)으로 검수한다.

## 2. 폴더 배치 (운영 모드, 도구에 `--prod`)
| 경로 | 내용 | git |
|---|---|---|
| `config/slide-v2/<책id>/skeleton.html` | 공통 뼈대(글꼴·편집 모드·컨트롤러·진행 표시). 자리표시자 `{{TITLE}}` `{{CSS}}` `{{SLIDES}}` `{{N}}` | 올림 |
| `config/slide-v2/<책id>/base.css` | 공통 스타일(테마 색·`.lb` 라벨 알약 등) | 올림 |
| `config/slide-v2/<책id>/assets/<이름>.svg` | 여러 슬라이드·단원이 같이 쓰는 그림(마스코트·장식) | 올림 |
| `library/<책id>/<단원>/slides.v2/slides.v2.json` | 목차(메타) | 올림 |
| `library/<책id>/<단원>/slides.v2/slides/sNN.html` | 슬라이드 하나의 본문 조각 | 올림 |
| `library/<책id>/<단원>/slides.v2/figures/<ID>.svg` | 이 단원에만 쓰는 내용 그림(파일 하나 = 그림 하나) | 올림 |
| `library/<책id>/<단원>/slides.html` | **빌드 결과**. 직접 고치지 않는다. 앱이 읽는 파일 | 올림 |
- 검수 중인 작업 공간은 같은 구조를 `drafts/<책id>/<단원>/slides.v2/`에 두고, 통과하면 `library`로 옮긴다.
- 새 책의 공통 파일은 같은 과목의 기존 `config/slide-v2/<책id>/`를 복사해 테마 색만 `config/slide-style-<과목>.md`에 맞게 바꿔서 시작한다(같은 과목이 없으면 과학 것을 복사해 스타일 문서대로 바꾼다).

## 3. 파일 형식
**목차 `slides.v2.json`** (기존 양식을 복제해 확장한 것):
```json
{
 "schema": "slides-v2/1",
 "book": "g1s2-science", "unit": "u4",
 "title": "물질의 상태 변화", "titleFull": "물질의 상태 변화 - 교과 정리",
 "budget": {"min": 10, "max": 12},
 "slides": [
  {"id": "s01", "file": "slides/s01.html", "class": "slide cover active", "style": null},
  {"id": "s02", "file": "slides/s02.html", "class": "slide", "style": "--z:1.1"}
 ]
}
```
- `titleFull`은 `<title>`과 단원명 규칙(교과서 차례 표기와 같음)을 따른다. `budget`은 과목 기준(도덕 11~12, 나머지 10~12)이다.
- 슬라이드 순서는 `slides` 배열 순서다. 번호 주석(`<!-- === n === -->`)과 `#count`의 총 장수는 빌드가 만든다(손으로 쓰지 않는다).

**본문 조각 `slides/sNN.html`**: `<section …>` 안쪽만 쓴다(`section` 태그와 속성은 목차가 가진다). 마크업은 v1과 같다(`.lb` 라벨, `.pg` 쪽 번호 등).
- 그림 자리: 이 단원 그림은 `{{figure:<ID>}}`, 공통 그림은 `{{asset:<이름>}}`. 그림 코드(`<svg>`)를 조각 안에 직접 쓰지 않는다.
- ID 이름: `<단원>-sNN-<번호>` (예 `u4-s05-1`). 같은 그림이 두 단원에서 쓰이면 `assets/`로 옮긴다.

## 4. 작성 규칙
1. **원본은 `notes.md` 하나뿐이다.** 슬라이드에 notes에 없는 사실을 쓰지 않는다.
2. **분량 예산을 처음부터 지킨다.** 표지 포함 `budget` 안(10~12장, 도덕 11~12장)으로 설계한다. 만든 뒤에 줄이지 않는다(예산 초과는 빌드가 ⚠).
3. **빠짐없음:** notes의 핵심 개념·시험 포인트가 슬라이드 텍스트에 모두 나와야 한다(`python engine/coverage_check.py <책> <단원>`의 슬라이드 커버율로 확인, 미커버는 이유가 있을 때만 남긴다).
4. **그림:** 한 파일에 그림 하나, `viewBox` 필수, 글자는 그림 폭 안에 들어가게, `transform`은 되도록 쓰지 않는다(쓰면 자동 점검을 못 하므로 눈으로 확인), 화살표 라벨은 선을 가로지르지 않게. 빌드의 그림 점검이 ✖ 0건이어야 한다.
5. **스타일·모바일 규칙은 `base.css`에만** 둔다. 단원 조각에 `<style>`을 쓰지 않는다(예외는 조각 하나에 한정한 인라인 `style` 속성뿐).
6. 스타일을 바꾸려면 `base.css` 한 곳을 고치고 해당 책의 모든 단원을 다시 빌드한다. 단원별로 스타일을 다르게 하지 않는다.

## 5. 빌드·점검
```
python engine/slides_v2.py build <책id> [단원 ...] --prod     # 조립 + 점검, ✖면 종료 코드 1이고 slides.html을 만들지 않는다
python engine/slide_integrity.py <책id> [단원]                # 완성된 slides.html 무결성(기존 도구)
python engine/coverage_check.py <책id> <단원>                 # 슬라이드 커버율
```
빌드 점검: 자리표시자 누락, 그림 XML 형식, `<section>` 개수, 장수 예산, 그림 글자 잘림·박스 겹침·선과 글자 교차(문항 SVG와 같은 점검기). `slides.html`이 바뀌었으면 `build_library.py`가 연결한다.

## 6. 검수
- 기계 관문(`python engine/gate.py <책> <단원>`)에 슬라이드 무결성이 들어 있다. 빌드 ✖ 0건 + gate 통과 + 슬라이드 커버율 점검을 마친 뒤에 사람이 보는 검수를 한다.
- 검수자는 완성된 `slides.html`(화면)과 `notes.md`를 대조해 사실 오류·빠진 핵심·가독성(최소 24px, 모바일 카드 배치)을 본다. 수정은 해당 조각·그림 파일만 고쳐 다시 빌드하고, 재검수는 바뀐 조각만 본다.

## 7. 기존(v1) 슬라이드를 v2로 옮기기
1. 시범 모드로 분해·비교: `python engine/slides_v2.py extract <책> [단원]` → `compare <책>`. 조립 결과가 기존과 같거나(스타일 블록만 다름) 본문이 같을 때만 진행한다.
2. 운영 배치로 분해: `python engine/slides_v2.py extract <책> --prod` → `build <책> --prod` → `slide_integrity.py`·`build_library.py` 통과, 앱에서 한 번 열어 확인.
3. 옮긴 뒤에는 `slides.html`을 직접 고치지 않는다(다음 빌드가 덮어쓴다).
