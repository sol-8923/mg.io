# 민겸이 공부 공간 — 콘텐츠 제작 작업 보고서

작성일 2026-11-17 · 대상: 문제 은행(출제)·오답풀이·오답노트·교과 정리 슬라이드를 **어떻게 만들고 검수하고 고치는지**
근거: `.claude/`(스킬·에이전트), `engine/`(스크립트), `docs/`(기준 문서), 이번 도덕 ① 작업 기록. 문서 속 날짜는 사용자 결정일이다.

---

## 1. 한눈에 보기

```
교과서·자습서·기출(materials/)  ──[/study]──▶  drafts/ (작업 공간, git 제외)
   │                                              │ ① 차례 확정·단원 구분(units.md)
   │ 기출: 전사·패턴 분석                          │ ② 핵심 정리 notes.md
   ▼                                              │ ③ 설계도 blueprint.json (exam-designer)
past-exams.md / exam-patterns.md                  │ ④ 문제 은행 questions.json (study-quiz, qgen.py)
                                                  │ ⑤ 오답풀이·참고 자료 (study-explain)
                                                  │ ⑥ 기계 점검 (build_library --check-unit, precheck_unit)
                                                  │ ⑦ 검수 에이전트 (형식·내용·종합·오답풀이) — 만장일치 필요
                                                  ▼
                                      library/<책>/<단원>/  ──[build_library.py]──▶ book.json·catalog.json
                                                  │                                   │
                                      교과 정리 slides.html (책이 끝난 뒤 따로)          ▼
                                                                          커밋·push → GitHub Pages → 웹앱
웹앱: 시험(매번 새 조합) → 결과 → 오답풀이 → 오답노트(두 번 연속 맞히면 졸업)
```

핵심 원칙 3가지
1. **학교 기출이 최우선이다.** 과목별 기출 분석(`docs/subjects/<과목>.md` 0번 절)이 다른 모든 규칙보다 앞선다.
2. **통과한 것만 library로 간다.** 검수 에이전트가 모두 PASS해야 하고, 작업 중인 것은 `drafts/`(git 제외)에 둔다.
3. **새 기준이 생기면 즉시 문서에 날짜와 함께 적는다.** 그래야 다음 단원부터 같은 기준을 쓴다.

## 2. 명령 키워드별 실제 동작

"명령 키워드"는 슬래시 명령(`/study`)과, 이 작업에서 정해 쓴 이름(B개정, 표본 감사 등)을 함께 적었다. 슬래시 명령은 `/study` 하나뿐이고, 나머지는 **그렇게 말하면 Claude가 해당 문서의 절차대로 움직이는 작업 이름**이다.

| 키워드 | 한 줄 정의 | 실제로 하는 일 (순서) | 산출물 | 근거 문서·도구 |
|---|---|---|---|---|
| `/study <학년> <학기> <과목> [단원]` (출제) | 한 과목의 문제 은행·오답풀이를 처음부터 만든다 | ① materials 확인 ② 교과서 차례를 이미지로 읽어 단원 번호·이름 확정(`meta.json`의 `textbookUnits`) ③ 단원 구분(`units.md`) ④ 기출 정리(있으면) ⑤ 단원별 notes → 설계도 → 문항 → 오답풀이 ⑥ 기계 점검 ⑦ 검수 ⑧ 통과 단원만 library로 이동·빌드·push | `drafts/<책>/<단원>/…` → `library/<책>/<단원>/` | `.claude/skills/study/SKILL.md` |
| 보강 모드 (같은 명령 재실행) | 이미 있는 단원에 변형 문항을 더한다 | 기존 문항은 두고 슬롯마다 변형을 추가, 새 문항만 다시 검수 | questions.json 갱신 | study 스킬 |
| 기출 편입 (0-B) | 학교 기출을 패턴 학습과 문항 편입에 쓴다 | 시험지 전사(스캔 PDF는 이미지 판독, hwp는 변환) → `past-exams.md`(문항·정답·단원·처리 상태) → `exam-patterns.md`(출제 경향) → 설계도 슬롯의 `pastExams`에 전부 배정 → 변환 문항 출제 → 처리 상태를 `포함:<문항id>`/`제외:<사유>`로 갱신 | past-exams.md, exam-patterns.md | study 스킬 0-B, `docs/출제-반려-예방.md` §6·§9 |

| 축약 검수 | 사용자가 그 작업에 한해 지시했을 때만 검수를 줄인다 | `status.json`에 `"mode":"reduced"`와 사유, `sample:true` 표시 | — | study 스킬 R8 |

## 3. 만드는 방법과 기준

### 3-1. 문제 출제 (study-quiz + exam-designer + qgen)
- **설계도(blueprint.json)**: `exam-designer`가 만든다. 슬롯 수·유형·난이도·배점·`variantsPerSlot`·사실 배분표(`facts`)·정답 번호 배분. 기출이 있으면 그 단원 기출 문항이 **전부** 슬롯의 `pastExams`에 배정돼야 한다(빌드가 검사).
- **문항(questions.json)**: 슬롯마다 **서로 다른 변형 여러 개**(기본 2개). `engine/qgen.py`의 도우미(`K`)로 단원 폴더의 `gen.py`가 생성한다. 그림·표는 SVG로 새로 그린다(교과서 그림 복제 금지).
- **지문 규칙(사용자 지시)**: 특정 사례·글·자료를 묻는 문항은 그 자료를 문항에 직접 넣는다. 실존 인물·학교명 금지. 의견·가치 판단을 정답으로 하는 문항 금지(도덕).
- **공통 반려 예방** (`docs/출제-반려-예방.md`, 국어·사회·과학·수학·기출 편입 검수의 반려 사유를 계속 누적): 슬롯 간 정답 노출, 합답 구성, 정답이 단독 최장, 정답 번호 쏠림·3연속, SVG 글자 잘림, 인용 쪽수, 서술형 채점 합=배점 등. 자동 점검이 있는 것은 `precheck_unit.py`가 ✖로 막는다.
- **과목별 기준** (`docs/subjects/<과목>.md`): 0번 기출 유형(시험 구성·난이도 배분·문형·배점)이 최우선, 그다음 출제 형식·지문 규칙·반려 사유·개선 이력. 도덕은 `docs/도덕-출제-기준.md`가 추가된다.
- **도덕의 현재 규칙**: 객관식 2~3점(1점 문항 없음, 2점은 난이도 하·중 혼재 허용), 논술 20점 택1, 부정형 30~35%, 사상가 연결 단원당 1~2개, 시험 최대 30문항.

### 3-2. 오답풀이·오답노트 (study-explain)
- 문항마다 `explanation`(왜 틀렸나), `detail`(정답 풀이 3문장 이상), `choiceExplanations`(보기별 — 오답마다 구체적 이유), `tip`, 서술형은 `rubric`·`modelAnswer`, 그리고 풀이 옆에 띄울 `refs`(그림·표·개념 카드).
- 섞이는 보기를 ①~⑤ 번호로 가리키지 않는다(`fixedOrder`가 아니면). 교과서 밖 뜻풀이는 `(교과서 밖 일반 상식)`을 붙인다. 학생이 보는 풀이의 근거는 학생용 교과서 쪽수로만 적는다(지도서·교사용 교과서를 근거로 적지 않음).
- 정책(2026-11-16): 해설·refs에서 다른 문항의 정답 개념을 풀어 쓰는 것은 결함이 아니다. 단 **문항 본문**(발문·지문·보기·캡션)의 정답 노출은 결함이다.
- 오답노트는 앱이 자동으로 만든다(별도 제작 없음). 오답풀이 작성 품질이 오답노트의 질을 결정한다.

### 3-3. 교과 정리 슬라이드 (frontend-slides + 과목 전용 스타일)
- **공통**: 1920×1080 고정 무대를 화면에 맞춰 축소, 본문 최소 24px, 폭 820px 이하 세로 화면은 세로 스크롤 카드로 전환, 키보드·터치 이동·편집 모드(E), 펜 필기 호환. 배포(Vercel)·PDF 변환은 하지 않는다.
- **과목별 스타일**: 교과서 표지의 메타포를 따른다 — 사회=하이킹 지도, 국어=과자 봉지 속 놀이공원, 과학=우주 남색 무대, 도덕=구름 낀 풀밭(마음의 산책), 수학은 `config/slide-style-math.md`.
- **내용 원칙**: 슬라이드의 문장·표·그림 라벨은 `notes.md`에 근거해야 한다(없는 사실 금지). 꼬리표('암기', '정리', '주의' 등)는 굵은 글씨가 아니라 `<span class="lb">` 알약으로 분리한다. 단원 번호는 교과서 차례 표기를 그대로 쓴다.
- **분량**: 단원당 11~12장(도덕 기준: 개요 없음, 개념도 2개, 구분하기 1장, 시험 포인트·핵심 정리 1장).
- **제작 순서**: 슬라이드는 단원 검수 때 만들지 않고 **책의 모든 단원이 library에 올라간 뒤** 한꺼번에 만든다(검수 비용 절감).

## 5. 에이전트 구성과 역할

### 5-1. 정의된 에이전트 (`.claude/agents/`)
| 에이전트 | 모델 | 도구 | 역할 |
|---|---|---|---|
| `exam-designer` | Sonnet | Read·Glob·Grep·Write | 문제를 쓰지 않고 **시험 설계도**만 만든다(슬롯·유형·난이도·배점·변형 수·사실 배분표, 기출 배정) |
| `review-content` | **Opus** | Read·Glob·Grep | **내용 검수**: 정답·해설·모범 답안이 교과서 원문과 맞는지, 복수 정답·사실 오류, 기출 변환 문항은 원본과 일치하는지 |
| `review-format` | Sonnet | Read·Glob·Grep·Bash | **형식 검수**: 오탈자, 정답 중복·누락, 보기 형식, 정답 위치 쏠림, 데이터 오류. `docs/subjects/README.md` 절감 규칙상 기계 점검으로 대체 가능 |
| `review-overall` | Sonnet | Read·Glob·Grep | **종합 검수**: 설계도대로 구성됐는지, 실제 내신처럼 느껴지는지, 난이도 표시, 슬롯 간 정답 노출, 서술형과 선택형 겹침, 기출 반영 여부 |
| `review-explanation` | Sonnet | Read·Glob·Grep | **오답풀이 검수**: 정답 풀이·보기별 해설·팁·참고 자료(SVG)가 문항과 맞는지 |

### 5-2. 실제 운영 방식 (이번 도덕 ① 작업 기준)
- 위 정의 파일은 **지침서**로 쓰였다. 실제로는 범용 에이전트를 띄워 "이 파일을 읽고 그대로 따라 검수하라"고 지시하고 모델(내용=Opus, 나머지=Sonnet)을 지정했다.
- **역할별 임시 에이전트**
  - 기출 전사 1명(PDF·hwp 판독, 패턴 분석)
  - 단원 제작자 단원당 1명(notes → 설계도 → 문항 → 오답풀이 → 기계 점검; 병렬 10명)
  - 단원별 검수자 4명(형식·내용·종합·오답풀이)
  - 수정 담당(반려 지적 반영, 제작자를 이어서 쓰기도 함)
  - 슬라이드 스타일·파일럿 1명, 슬라이드 제작 9명, 슬라이드 내용 검수 10명
  - B개정·표본 감사 수정 담당과 감사 검수자
- **코디네이터(메인 세션)의 일**: 에이전트 호출, 보고 취합, 기출 처리 상태(`past-exams.md`) 갱신, 반려 사항을 수정 에이전트에 전달, library 이동·빌드·커밋·push, 사용자 결정 반영.
- 병렬은 동시 20개가 한도라 검수와 수정을 나눠 보냈다. 검수 에이전트는 **읽기 전용**(파일을 고치지 않고 보고만).

### 5-3. 알려진 운영 한계
- 하위 에이전트는 보고서 **파일을 쓸 수 없어서**(도구가 막음) 결과를 텍스트로 받아 코디네이터가 저장했다.
- 에이전트는 서로의 임시 파일을 지우지 않고 `taskkill` 같은 프로세스 종료는 하지 않는다. 임시 파일은 scratchpad에만 둔다.

## 9. 남은 과제와 보류 사항

1. **휴대폰 화면 확인**: 슬라이드·결과 화면의 모바일(폭 390px)을 이 PC 환경에서 재현하지 못해 실기기 확인이 필요하다.
2. **3점 부정형 소거형 허용 여부**: 정답만 분명히 부정적인 3점 문항(`도덕.md` 0-4 ③)은 사용자 결정 보류.
3. **문항 옆 배점 칩**은 문항 배점(원점수)으로 남겨 두었다(100점 기준 표기와 별개).
4. **과학·영어 도덕 외 자료**: 새로 받은 과학·영어 자료는 아직 `/study`를 하지 않았다.
5. **새 반려 사유 환류**: 이번 검수에서 나온 NEW-RULE(서술형·선택형 겹침, 양방향 대조, 이름 변경 시 조사 점검 등)를 `출제-반려-예방.md`와 `precheck`에 옮기는 작업.
6. **기출 변환 방침 차이**: 도덕은 표현을 바꿔 편입했지만 README의 기출 원문 편입 규칙은 "원문 그대로"다. 둘을 하나로 정해야 한다.
7. **슬라이드 모바일·편집 모드(E)·키보드 이동**은 코드 복제만 하고 직접 눌러 보지 못했다.
