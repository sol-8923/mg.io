# 시험공부 자료 만들기 (/study)

사용법: `/study <학년> <학기> <과목> [<단원> ...]` — 예: `/study 1학년 2학기 과학` (폴더의 자료 전체), `/study 1학년 2학기 과학 2단원` (특정 단원만)
이미 있는 단원은 **보강 모드**: 기존 문제는 두고 슬롯마다 변형 문제를 더 추가한다.

## 앱이 동작하는 방식 (만들 때 꼭 알아야 할 것)
- 사이트: `https://sol-8923.github.io/mg.io/study/` — 홈 → 시험으로 풀어보기(책장) → 책(시험 범위 선택) → 시험 → 결과 → 오답풀이(한 문제 한 페이지, 옆에 참고 자료) / 오답노트
- **시험지는 들어갈 때마다 새로 조합된다.** 설계도의 슬롯마다 은행의 변형 문제 중 하나를 고르고(최근에 덜 본 것 우선), 선택형 보기 순서를 섞는다. 그래서:
  - 슬롯마다 변형 문제가 **여러 개**(기본 2개 이상) 있어야 한다.
  - 보기가 섞이므로 해설에서 보기를 **번호(①~⑤)로 가리키면 안 된다.** 보기 내용으로 가리키거나, 순서가 의미 있는 문항(ㄱㄴㄷ 조합, A~E 기호, 크기순)은 `fixedOrder: true`.
- 오답노트·기록은 각 기기(localStorage)에 저장된다. 서버는 없다.

## 폴더
| 경로 | 내용 |
|------|------|
| `materials/<n>학년/<n>학기/<과목>/` | 원문: 교과서·자습서 사진, PDF, 텍스트. 단원 구분 없이 넣어도 됨 (git 제외) |
| `materials/<n>학년/<n>학기/<과목>/기출/` | 학교 기출문제 (git 제외). 시험지 사진·PDF, 답지가 있으면 함께 |
| `drafts/<책id>/past-exams.md` | **기출 문항 목록**: 전사(옮겨 적기)·정답·단원·처리 상태 (git 제외, 0-B단계) |
| `drafts/<책id>/exam-patterns.md` | **기출 패턴 분석**: 출제 경향·발문·자료 형태·함정 (git 제외, 0-B단계) |
| `drafts/<책id>/` | **검수 중인 작업 공간** (git 제외). `meta.json` + 단원 폴더(`notes.md`, `blueprint.json`, `questions.json`, `slides.html`, `review/`) |
| `library/<책id>/<단원id>/` | **검수를 통과한 단원만** 옮겨 둔다(`review/status.json` = PASS). 사이트에 공개되는 곳 |
| `library/<책id>/book.json`, `library/catalog.json` | 빌드 결과 (직접 수정 금지) |

- 책id: `g<학년>s<학기>-<과목영문>` — 예: `g1s2-science`. 과목영문: 국어 korean, 영어 english, 수학 math, 과학 science, 사회 social, 역사 history, 도덕 ethics, 기술·가정 tech-home, 정보 info, 한문 hanmun
- 단원id: `u<번호>` — 예: 2단원 → `u2`. 문항 id: `<단원id>-<슬롯>-<a,b,c…>` — 예: `u2-Q03-b`
- 책이 처음이면 `meta.json`을 만든다(학년·학기·과목). 과목 색은 앱 기본값을 쓰므로 생략 가능.

## 진행 순서

### 0단계 · 준비와 단원 구분
1. `materials/<n>학년/<n>학기/<과목>/`에 자료가 있는지 확인(`기출/` 제외). 없으면 넣을 위치를 안내하고 멈춘다.
2. 사진은 Read로 직접 읽고, PDF는 `pdf` 스킬. 판독이 안 되는 부분은 추측하지 말고 사용자에게 확인.
   **자료 종류는 파일 이름으로 판별해 쓰임을 달리한다.** (예: `[비상교육] 중학_국어 1-2(박현숙)_교과서.pdf`)
   | 이름에 들어 있는 말 | 성격 | 쓰임 |
   |---|---|---|
   | `교과서` | 학생이 보는 본문(제재, 학습 활동, 단원 마무리) | **출제 범위와 용어의 기준.** 핵심 정리(notes)와 문항의 근거 |
   | `교사용 교과서` | 교과서 본문 + 활동의 예시 답·해설·교수 포인트가 덧붙은 판 | 정답·모범 답안 확인, 서술형 채점 기준 초안, 오답풀이 근거 |
   | `지도서` | 성취기준, 단원 지도 계획, 평가 계획·평가 기준(상·중·하), 평가 문항 예시 | 설계도(슬롯 개념·난이도·서술형 비중) 설정, 서술형 `rubric` 작성, 내신 출제 방향 참고. 지도서의 평가 문항 예시는 출제 방식 참고용이며 그대로 베끼지 않는다 |
   | `자습서`·`평가문제집`·`문제집` | 교과 정리·확인 문제 | 핵심 정리와 문제 유형 참고 (있을 때만) |
   | 같은 폴더의 이미지(jpg·png) 한 장 | 교과서 표지 | 앱 책 표지로 자동 사용 (`build_library.py`가 복사) |
   PDF는 `pdftotext -enc UTF-8 [-layout] <파일> <출력.txt>`로 텍스트를 뽑아 쓴다(내 PC의 `/ucrt64/bin/pdftotext`). 터미널에서는 한글이 깨져 보일 수 있으니 반드시 파일로 저장해서 읽는다. 다단 편집 쪽은 문장이 섞이고, 지도·그림 쪽은 글자가 깨질 수 있으니 그런 쪽은 `Read`로 쪽 이미지를 직접 보고 확인한다(추측 금지). 교과서가 여러 학기를 한 권에 담았으면(예: 사회①) 사용자가 정한 학기 범위의 대단원만 쓴다.
2-B. **교과서 차례 먼저 정리 (필수, 2026-11-16 사용자 지시)**: 새 교과서·새 과목을 시작하면 **무엇보다 먼저** 교과서 차례 페이지를 이미지로 뽑아(PyMuPDF `get_pixmap`) 직접 보고 단원 **번호·이름·순서·번호 표기(로마 숫자/아라비아 숫자)** 와 소단원 번호·이름을 확정한다. 학기에 상관없이 **교과서 전체 단원**을 적는다.
   - 결과를 `library/<책id>/meta.json`의 `textbookUnits`(`[{"no":4,"name":"…"}, …]`)에 넣는다. 앱은 이 목록으로 단원 목록을 번호 순서대로 보여 주고, 아직 안 만든 단원은 "준비 중"으로 둔다.
   - 단원 폴더 이름은 `u<교과서 단원 번호>`(예: 수학 4단원 → `u4`)로 한다. 순번(1, 2, 3…)이 아니라 **교과서 번호**다. `blueprint.json`의 `unitName`은 차례의 단원명과 **글자 그대로** 같게 쓴다(공백만 무시). `build_library.py`가 어긋나면 오류로 막는다.
   - 표기: 사회·과학은 로마 숫자(Ⅰ~), 수학·국어는 아라비아 숫자. 소단원 번호는 교과서 방식 그대로(사회·국어 `01`, 수학 `4.1`, 과학 `1`/`01`). 슬라이드 표지·kicker·개요 카드도 이 이름과 번호를 그대로 쓴다.
   - 어느 학기에 어떤 단원을 만들지(범위)는 이 정리 **뒤에** 정한다. 범위가 애매하면 사용자에게 학교 진도를 묻는다.
3. **단원 구분**: 교과서 차례·단원 표지·쪽 번호·자습서 단원명으로 각 자료가 어느 단원인지 정한다. 결과를 `drafts/<책id>/units.md`에 표로 남긴다(단원id `u1, u2…`는 교과서 순서, 단원명은 교과서 표기, 해당 파일·쪽). 애매한 자료는 사용자에게 확인한다.
   - 이미 `library/<책id>/`에 있는 단원은 그 단원id·단원명을 그대로 쓴다(보강 모드).
4. 책이 처음이면 `drafts/<책id>/meta.json`을 만든다(학년·학기·과목). 기존 단원 보강은 `library/…/<단원id>/`를 `drafts/`로 복사해서 작업한다.
5. 모든 문항에는 `unit`(단원id)이 붙는다 — 빌드가 단원 폴더 이름으로 자동 기록하므로 문항을 **반드시 해당 단원 폴더**에 넣는다. 학생 화면에는 보이지 않고, "새로운 시험 보기"의 시험 범위 선택과 대시보드 단원별 통계에 쓰인다.

### 0-B단계 · 기출 정리 (`기출/`에 파일이 있을 때) — 두 가지 용도
기출은 ① **출제 패턴 학습**(새 문항의 질 향상)과 ② **기출 문항 자체를 문제 은행에 넣기**(검수 대상 포함) 두 가지로 쓴다.
1. **전사** → `drafts/<책id>/past-exams.md`. 기출 문항을 하나도 빠짐없이 표로 옮긴다(drafts는 git 제외라 원문 그대로 적어도 된다).
   - 열: `ref`(`<연도>-<학기>-<중간|기말|기타>-<번호 두 자리>`, 예 `2025-1학기-기말-07`) · 단원id · 유형 · 개념 · 발문·보기·자료 요약 · 기출 정답 · 정답 근거(답지/원문 확인) · **처리**(`대기`/`포함:<문항id>`/`제외:<이유>`)
   - 답지가 없으면 원문으로 정답을 직접 판단하고 "답지 없음"이라고 적는다. 판독이 안 되는 문항은 추측하지 말고 사용자에게 확인한다.
   - 단원은 `units.md` 기준으로 정한다. 여러 단원에 걸친 문항은 주된 단원 하나에 넣는다. **이번 자료에 없는 단원**의 문항은 `대기`로 남겨 두고 그 단원을 만들 때 넣는다.
   - `제외`는 범위 밖(교육과정·교과서에 없음), 판독 불가처럼 **넣을 수 없는 경우만** 쓴다. 어렵거나 형식이 특이하다는 이유로는 빼지 않는다.
2. **패턴 분석** → `drafts/<책id>/exam-patterns.md` (`exam-designer`가 처음 실행될 때 작성, 기출이 추가되면 갱신). 책 전체에 공통으로 쓴다.
3. 기출이 새로 추가된 상태에서 다시 실행하면 처리 상태가 `대기`인 기출만 처리한다. 이미 library에 있는 단원은 **보강 모드**로 기출 변환 문항을 추가하고 다시 4중 검수를 받는다.

### 1단계 · 핵심 정리 → `notes.md`
발표·시험·오답풀이의 **공통 원본**. 모든 사실에 출처 쪽수. 원문에 없는 내용 금지.
`## 단원 개요 / ## 핵심 개념(정의·설명·예시·출처) / ## 꼭 외울 것 / ## 헷갈리기 쉬운 것(비교표) / ## 자주 하는 오해 / ## 시험 포인트`

### 2단계 · 내신 시험화 → `blueprint.json`
`exam-designer` 에이전트 호출 (notes.md, materials 경로, `기출/` 폴더 경로, `past-exams.md`·`exam-patterns.md` 경로 전달). 슬롯·배점·난이도·`variantsPerSlot`이 정해진다.
- 기출이 있으면 이 단원의 기출 문항이 **전부** 슬롯의 `pastExams`에 배정된다(빌드가 검사).

### 3단계 · 문제 은행 출제 → `questions.json`
`study-quiz` 스킬. 슬롯마다 `variantsPerSlot`개 이상의 **서로 다른** 변형 문제. 그림·자료(SVG)를 적극 활용한다.
- 기출이 있으면 **(1) 기출 변환 문항**(`origin: "past-exam"`)을 먼저 만들고, **(2) 나머지 변형은 `exam-patterns.md`의 패턴을 따라** 새로 만든다. 끝나면 `past-exams.md` 처리 상태를 `포함:<문항id>`로 바꾼다.

### 4단계 · 오답풀이 작성
`study-explain` 스킬. 모든 문항에 상세 풀이·보기별 해설·자주 하는 오답·기억할 점·**참고 자료(refs)**를 채운다.

### 5단계 · 교과 정리 → `slides.html`
> 디자인 작업이므로 **Sonnet** 서브에이전트에 맡겨도 된다(사용자 허용).
`frontend-slides` 스킬. 고정값: High density / reading-first, 입력은 notes.md, Vercel 배포·PDF 변환은 쓰지 않음. 스타일은 `config/slide-style.md`(없으면 첫 실행 때 정해 저장). 한글 글꼴 사용.

### 6단계 · 빌드 검사
`python engine/build_library.py --check-unit drafts/<책id>/<단원id>` — `✖`가 없을 때까지 3·4단계로 돌아가 고친다. (1~7단계의 모든 작업 경로는 `drafts/<책id>/<단원id>/`)

### 7단계 · 4중 검수 (만장일치)
> **모델 배정(사용자 지정):** 내용 검수(`review-content`)만 **Opus**, 형식·종합·오답풀이 검수는 **Sonnet**. 에이전트를 이름으로 못 부르는 환경에서 general-purpose로 대신 실행할 때도 같은 모델을 지정한다.
1. `review-format`, `review-content`, `review-overall`, `review-explanation` 네 에이전트를 **한 번에 동시에** 호출. 서로의 결과는 전달하지 않는다.
   - 전달: 책id·단원id, materials 경로, `drafts/<책id>/<단원id>/` 경로, `기출/` 경로·`past-exams.md`·`exam-patterns.md`(있으면), 라운드 번호. 보강 모드면 새로 추가된 문항 id 목록도.
   - **기출 변환 문항도 일반 문항과 똑같이 4중 검수 대상**이다. 기출이라고 검수를 건너뛰지 않는다. 추가로 내용 검수는 기출 원본과의 일치(정답·핵심 자료), 종합 검수는 기출 누락 여부와 패턴 반영을 본다.
2. 보고서를 `drafts/<책id>/<단원id>/review/round-<N>-<format|content|overall|explanation>.md`로 저장.
3. **넷 모두 `VERDICT: PASS` → 통과.** 하나라도 REJECT → 되돌림 후 N+1 라운드. **횟수 제한 없음.**
   - **예외 (사용자 지정 규칙):** `review-overall`이 REJECT여도 지적 사항이 **난이도에 관한 것뿐**(난이도 표시의 타당성, 변형 간 난이도 차이, 상/중/하 체감)이면 통과로 본다. 이때 그 지적은 고치지 않고 `review/changelog.md`에 "난이도 참고"로 기록만 한다. 난이도 외의 지적(답 노출, 개념 중복, 변형 복제, 설계도 위반, 선택지 구성 결함 등)이 하나라도 섞여 있으면 평소처럼 반려한다.

### 되돌림 규칙
| 되돌릴 곳 | 처리 |
|-----------|------|
| `notes` | notes.md 수정 → 영향받는 문항·풀이·슬라이드도 수정 |
| `blueprint` | `exam-designer`에 지적 전달 → 바뀐 슬롯 문항 재출제 |

| `slides` | slides.html 해당 부분 수정 |
| `user` | 쟁점과 원문 근거를 보여 주고 사용자 결정 |
| `past-exam` | 기출 전사·단원 배정·처리 상태 오류 → `past-exams.md` 수정 → 해당 슬롯 문항 수정 |
- **기출 정답이 교과서와 다르거나 기출 문항 자체에 오류(복수 정답 등)가 있으면** 임의로 고치지 말고 `user`로 올린다. 사용자가 정한 대로 고친 뒤 `review/changelog.md`에 "기출 원본과 다르게 수정: 이유"를 남긴다.
- 검수자끼리 반대되는 지적은 원문을 다시 확인한다. **같은 쟁점이 두 라운드 연속 해결되지 않으면** 사용자에게 결정을 받는다(교착 해소용, 횟수 제한 아님).
- 수정마다 `review/changelog.md`에 한 줄씩 기록.

### 8단계 · 통과 단원 옮기기 · 빌드 · 배포 · 확인
> 옮기기·빌드·커밋·push는 **Sonnet** 서브에이전트에 맡겨도 된다(사용자 허용).
0. **만장일치로 통과한 단원만** `drafts/<책id>/<단원id>/`를 `library/<책id>/<단원id>/`로 옮기고(`meta.json`도 처음이면 함께), `review/status.json`에 `{"verdict":"PASS","round":N,"date":"YYYY-MM-DD"}`를 기록한다. 통과하지 못한 단원은 drafts에 남겨 다음에 이어서 한다. 빌드는 통과 기록이 없는 library 단원을 거부한다.
1. `python engine/build_library.py <책id>` → `book.json`, `catalog.json` 생성
2. 로컬 확인: study 폴더에서 `python -m http.server` → 책장에 책이 보이고, 새로운 시험 보기·오답풀이·참고 자료가 정상 표시되는지 확인
3. 커밋 후 push (materials는 .gitignore로 제외). 1~2분 뒤 Pages 반영
4. 보고는 짧게: 은행 문항 수(슬롯×변형), 기출 반영(포함/대기/제외 개수), 검수 통과 라운드 수, 사용자 판단 쟁점, 주소

## 주의
- 저장소와 사이트는 **공개**다. 교과서 문장·그림을 그대로 옮기지 말고 요약·재구성한다. 교과서 사진은 SVG로 **새로 그린** 자료만 쓴다. `materials/`는 절대 커밋하지 않는다.
- 이름·학교 등 개인정보를 결과물에 넣지 않는다. 기출 변환 문항에도 학교명·교사명·반 정보를 남기지 않는다(`pastExamRef`는 연도·학기·시험·번호만).
- 중간에 멈추면 진행 상황을 `review/changelog.md`에 남겨 이어서 할 수 있게 한다.

## 개정 규칙 (2026-11-15)
`docs/내신-적합성-검토와-개정안.md`의 R2·R8·R9를 반영한다. 위 진행 순서에 **추가**한다.
- **2단계 보강 (R2)**: `exam-designer`가 슬롯마다 `facts`(정답 근거 사실)를 적은 설계도를 만든다. 3단계 출제가 끝나면 슬롯별 정답 사실이 다른 문항에서 참으로 단언되지 않는지 검색해 확인한 뒤 검수에 넘긴다.
- **축약 검수 (R8)**: 4중 검수를 줄이는 것은 **사용자가 그 작업에 한해 지시했을 때만** 한다. 이 규칙 문서는 바꾸지 않는다. 줄인 단원은 `review/status.json`에 `"mode": "reduced"`와 사유를 적고(빌드가 book.json의 `reviewMode`로 옮긴다), `review/changelog.md` 맨 위에 무엇을 생략하고 무엇으로 대신했는지, 알려진 한계를 적으며, 책은 `meta.json`의 `sample: true`로 둔다. 정식으로 쓰려면 보강 모드로 다시 돌려 4중 검수를 받고 `mode`를 지운다. 축약 점검에서는 숫자·연도·원문 대조를 **코드로** 하고, 코드 검사기가 내 정답과 같은 규칙으로 만들어져 독립 검증이 아닐 때는 changelog에 그렇게 적는다.
- **교과서 용어 우선 (R9)**: 교과서·자습서가 있으면 그 용어와 수준을 따른다. 저작권 때문에 공개 자료(위키백과 등)만 쓴 경우 notes.md 첫머리에 '교과서 용어와 다를 수 있음'을 적고 출처·라이선스를 밝힌다.

## 절감 규칙 (2026-11-15, 사용자 승인 — 품질 기준은 그대로, 진행 방식만 변경)
국어 1단원이 4개 검수 6라운드가 걸려, 같은 품질을 더 적은 사용량으로 얻도록 아래를 위 진행 순서에 **덮어쓴다**.
1. **6단계에 사전 점검을 추가**: 검수 전에 `python engine/precheck_unit.py <책id> <단원id> --pages <시작-끝> [--offset <PDF쪽-인쇄쪽>]`를 돌려 **✖가 0건**이 되게 한다. 원문 인용이 교과서에 실제로 있는지, 인용 옆에 적은 쪽수가 맞는지, 단답 정답·조건 낱말이 다른 문항에 새지 않는지, 풀이·해설이 너무 짧거나 똑같지 않은지, answerHint와 인정 답 길이가 맞는지, 설계도와 문항이 일치하는지를 자동으로 확인한다(⚠는 검수자가 판단). 1단계 notes.md도 **원문 문장을 직접 대조하며** 쓰고, 줄거리·표의 세부(순서, 시점, 인물 말)는 확인 안 된 것을 적지 않는다.
2. **7단계 재검수는 반려한 검수자만**: 1라운드는 4개 모두 실행한다. 2라운드부터는 **직전 라운드에서 REJECT한 검수자만** 다시 실행한다(통과한 검수자는 그 라운드의 통과가 유효하되, 이후 고친 문항·풀이가 그 검수자의 소관을 건드렸다면 그 검수자도 다시 실행). **반려한 검수자가 모두 통과하면 최종 확인 라운드로 4개를 한 번 더 실행**하고, 4개가 모두 PASS면 통과로 본다(최종 확인에서 반려가 나오면 위 규칙을 반복). 종합 검수의 '난이도만' 예외와 모델 배정(내용 검수만 Opus)은 그대로다.
3. **5단계 요약 슬라이드는 책의 모든 단원이 `library`에 올라간 뒤 한꺼번에 만든다.** 그동안 단원 검수에서는 slides 관련 항목을 생략하고(slides.html이 없는 것은 반려 사유가 아니다), 8단계 옮기기 때도 slides.html 없이 통과시킨다. 슬라이드가 없는 단원은 앱의 '교과 정리'에 나타나지 않는다.
4. 검수자에게 줄 지시에 **반려는 '정답이 틀림·사실 오류·정답 노출·규칙 위반'일 때만** 하고, 쪽수 표기 정밀도·풀이 문체·난이도·표현 취향은 '참고'로 적게 한다(판정에 넣지 않는다).

- **8단계(단원 통과 후, 커밋 전)**: 그 단원의 `review/` 보고서와 `changelog.md`를 보고 해당 과목 파일을 갱신해 같은 커밋에 넣는다 — ⓐ 일반화할 수 있는 반려 사유 → 5번 체크리스트, ⓑ 난이도 참고·참고 사항·사용자 지시 → 6번 '다음 단원에서 개선할 것'(이미 반영한 것은 7번 이력으로), ⓒ 7번에 한 줄 이력.
