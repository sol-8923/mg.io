# 시험공부 자료 만들기 (/study)

사용법: `/study <과목> <단원> [<단원> ...]` — 예: `/study 과학 2단원`, `/study 사회 3단원 4단원`

## 폴더
| 경로 | 내용 |
|------|------|
| `materials/<과목>/<단원>/` | 원문: 교과서·자습서 사진, PDF, 텍스트 (사용자가 넣음) |
| `materials/past-exams/<과목>/` | 학교 기출문제 (있으면) |
| `output/<과목>/<범위>/` | 결과물. `<범위>`는 단원 하나면 단원 이름, 여럿이면 `2단원+3단원` |
| `config/slide-style.md` | 발표 자료 스타일 (첫 실행 때 정함) |

## 진행 순서

### 0단계 · 준비
1. `materials/<과목>/<단원>/`에 자료가 있는지 확인한다. 없으면 어디에 무엇을 넣어야 하는지 안내하고 멈춘다.
2. 사진은 Read 도구로 직접 읽는다. PDF는 `pdf` 스킬을 사용한다. 글씨가 흐려 읽을 수 없는 부분은 추측하지 말고 목록으로 정리해 사용자에게 확인받는다.
3. `output/<과목>/<범위>/`가 이미 있으면 덮어쓰기 전에 확인받는다.
4. 학년이 자료에서 드러나지 않으면 기본값은 **중학생**이다. 정확한 학년(중1~3)을 모르면 한 번 묻는다.

### 1단계 · 핵심 정리 → `notes.md`
두 결과물(발표·시험)의 **공통 원본**이다. 발표에서 본 내용이 그대로 시험에 나오게 하는 핵심 단계.
```markdown
# <과목> <범위> 핵심 정리
## 단원 개요            — 이 단원에서 배우는 것 3~5줄
## 핵심 개념            — 개념마다: 정의 / 설명 / 예시 / (출처: 교과서 p.00)
## 꼭 외울 것           — 용어, 공식, 분류, 순서
## 헷갈리기 쉬운 것     — 비교표 (A vs B)
## 시험 포인트          — 자주 나오는 형태, 교과서가 강조한 부분(탐구·정리·확인 문제)
```
- 모든 사실에 출처 쪽수를 붙인다. 원문에 없는 내용은 넣지 않는다.

### 2단계 · 내신 시험화 → `blueprint.json`
`exam-designer` 에이전트를 호출한다. 전달: notes.md 경로, materials 경로, past-exams 경로(있으면).

### 3단계 · 발표 자료와 문제 출제 (서로 독립이므로 순서 무관)
**발표 자료 → `slides.html`**
- `frontend-slides` 스킬을 따른다. 단, 아래는 고정값이라 묻지 않는다.
  - 콘텐츠 밀도: **High density / reading-first** (혼자 읽으며 공부하는 자료)
  - 입력 내용: notes.md (원문을 직접 요약하지 않는다)
  - frontend-slides의 Vercel 배포·PDF 변환은 쓰지 않는다 (공개는 GitHub Pages로 한다 — 5단계)
- 스타일: `config/slide-style.md`에 저장된 스타일이 있으면 그대로 쓴다. 없으면(첫 실행) frontend-slides의 스타일 고르기 과정을 진행하고, 고른 결과를 `config/slide-style.md`에 저장한다.
- 구성: 표지 → 단원 개요 → 핵심 개념(개념당 1~2장) → 꼭 외울 것 → 헷갈리는 것 비교 → 시험 포인트 → 마무리 요약.
- 글꼴은 한글이 잘 보이는 것(Pretendard, Noto Sans KR 등)을 쓴다.

**문제 출제 → `questions.json` → `quiz.html`**
- `study-quiz` 스킬을 따른다. 빌드 스크립트가 통과할 때까지 고친다.

### 4단계 · 3중 검수 (만장일치)
1. `review-format`, `review-content`, `review-overall` 세 에이전트를 **한 번에 동시에** 호출한다. 각자 독립적으로 판단하도록 다른 검수자의 결과는 전달하지 않는다.
   - 전달: 과목·범위, materials 경로, output 경로, past-exams 경로(있으면), 라운드 번호.
2. 각 보고서를 `output/<과목>/<범위>/review/round-<N>-<format|content|overall>.md`로 저장한다.
3. 판정
   - **세 개 모두 `VERDICT: PASS` → 통과.** 5단계로.
   - **하나라도 REJECT → 반려.** 아래 "되돌림"을 진행하고 N+1 라운드로 다시 4단계. **횟수 제한 없음.**

### 되돌림 규칙
지적 사항을 `되돌릴 곳`별로 모아 처리한다. 처리 순서는 위에서 아래로(상위 단계를 고치면 하위도 다시 맞춘다).
| 되돌릴 곳 | 처리 |
|-----------|------|
| `notes` | 1단계 notes.md 수정 → 영향받는 슬라이드·문항도 함께 수정 |
| `blueprint` | `exam-designer`에 지적 사항 전달해 설계도 수정 → 바뀐 슬롯 문항 재출제 |
| `quiz` | `study-quiz` 스킬로 **지적된 문항만** 수정 → 빌드 |
| `slides` | slides.html의 해당 부분만 수정 |
| `user` | 사용자에게 쟁점과 원문 근거를 보여 주고 결정을 받은 뒤 반영 |

- 검수자끼리 서로 반대되는 지적을 하면(예: A는 "③이 정답", B는 "③은 오답") 임의로 고르지 말고 원문을 다시 확인한다. **같은 쟁점이 두 라운드 연속 해결되지 않으면** 사용자에게 쟁점을 정리해 보여 주고 결정을 받는다(횟수 제한이 아니라 교착 상태 해소용).
- 수정할 때마다 `review/changelog.md`에 라운드·대상·변경 내용을 한 줄씩 기록한다.

### 5단계 · 완료
1. `quiz.html`과 `slides.html`을 브라우저로 열어 정상 표시를 확인한다(E 드라이브 지침의 완료 확인 규칙).
2. 목록 페이지 갱신: `python engine/build_index.py` → `study/index.html`
3. 커밋 후 push한다(`materials/`는 .gitignore로 제외됨). GitHub Pages가 1~2분 뒤 자동 반영된다.
4. 보고는 짧게: 문항 수·총점, 검수 통과 라운드 수, 사용자 판단이 필요했던 쟁점(있으면), 그리고 주소
   - 목록: `https://sol-8923.github.io/mg.io/study/`
   - 해당 단원 시험·요약 주소 (경로의 한글은 브라우저가 자동 처리)

## 주의
- 저장소(mg.io)와 Pages는 **공개**다. 결과물(요약·문제)은 누구나 볼 수 있으므로, 교과서 문장·그림을 그대로 길게 옮기지 말고 **요약·재구성한 내용**으로 만든다. 교과서 사진 원본(`materials/`)은 절대 커밋하지 않는다.
- 이름·학교 등 개인정보를 결과물에 넣지 않는다.
- 중간에 멈춰야 할 때(자료 판독 불가, 사용자 판단 필요)는 진행 상황을 `review/changelog.md`에 남겨 다음에 이어서 할 수 있게 한다.
