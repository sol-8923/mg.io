# 문제 은행 출제 (study-quiz)

화면·채점·시험지 조합은 앱(`app/app.js`)이 한다. **이 스킬은 `drafts/<책id>/<단원id>/questions.json`의 문제 데이터만 만든다.**
오답풀이 항목(detail·choiceExplanations·refs 등)은 `study-explain` 스킬이 채우지만, 출제자가 의도를 알고 있으므로 초안을 함께 써 두면 좋다.

## 입력
- `blueprint.json` — 슬롯(id·type·difficulty·points·concept·intent), `variantsPerSlot`
- `notes.md` — 핵심 정리(출처 포함), `materials/…` — 원문
- 보강 모드: 기존 `questions.json` (기존 문항은 건드리지 않고 추가)
- (기출이 있으면) `drafts/<책id>/past-exams.md`, `drafts/<책id>/exam-patterns.md`, `materials/…/기출/` 원본

## 기출 활용 (기출이 있을 때)
### (1) 기출 변환 문항 — 슬롯의 `pastExams`에 적힌 기출마다 정확히 하나
기출 원본(`기출/` 사진·PDF)을 직접 보고 만든다. **실제 시험에 나온 문제를 그대로 풀어 보게 하는 것이 목적**이므로 핵심은 지키되, 공개 저장소에 올라가므로 표현은 다듬는다.
| 지킬 것 (바꾸면 안 됨) | 다듬을 것 |
|---|---|
| 묻는 개념과 방향, 정답, 오답 보기의 함정(오개념), 자료의 수치·구조, 〈보기〉 ㄱㄴㄷ 내용, 서술형 조건 | 문장 표현(뜻이 같게), 그림은 **SVG로 새로 그림**, 학교명·교사명·반·"○○쌤" 같은 표시 삭제, 명백한 오탈자 |
- 필드: `"origin": "past-exam"`, `"pastExamRef": "2025-1학기-기말-07"`(past-exams.md의 ref 그대로), `source`는 근거가 되는 **교과서 쪽수**(예: `"교과서 p.34 (2025 1학기 기말 7번 변환)"`).
- type·difficulty·points·concept는 슬롯 값을 따른다. 원래 배점과 달라도 된다.
- 기출의 보기가 4개면 5개로 늘리지 말고 그대로 둔다(빌드 경고는 무시 가능, 검수 참고 사항).
- 기출 정답이 교과서와 맞지 않거나 기출 자체에 오류(복수 정답, 조건 누락)가 있으면 **임의로 고치지 말고** 멈추고 보고한다(사용자 결정 사항).
- 만든 뒤 `past-exams.md`의 처리 상태를 `포함:<문항id>`로 바꾼다.

### (2) 새 변형 — `exam-patterns.md`의 패턴을 따른다
- 발문 말투, 자료 형태, 오답 보기에 쓰는 오개념, 서술형 조건 문구를 이 학교 스타일로 맞춘다.
- 기출 변환 문항과 **같은 슬롯의 새 변형**은 기출과 같은 개념·형태를 다른 사례·다른 수치·다른 〈보기〉로 묻는다(기출의 숫자만 바꾼 복제 금지).
- 기출에서 반복 출제된 개념은 다른 슬롯에서도 다른 각도로 다뤄 대비시킨다.

## 변형 문제 원칙 (문제 은행의 핵심)
- 슬롯마다 `variantsPerSlot`개 이상. 같은 슬롯의 변형끼리 **type·difficulty·points·concept는 같고**, 나머지는 달라야 한다.
- 변형은 **표현만 바꾼 복제가 아니다.** 다른 사례, 다른 자료(수치·그래프·표), 다른 〈보기〉 조합, 묻는 방향 바꾸기(옳은 것 ↔ 옳지 않은 것, 원인 ↔ 결과).
- 같은 슬롯의 변형이 같은 시험지에 함께 나오지는 않지만, **다른 슬롯 문항의 답을 알려주면 안 된다.**

## 실제 내신 문항 스타일 가이드
학교 시험은 단순 용어 묻기보다 **자료를 주고 해석·적용**하게 한다. 단원마다 아래 형태를 골고루 쓴다.
| 형태 | 예 | 데이터 |
|------|----|--------|
| 그래프 해석 | 가열·냉각 곡선 구간, 시간-거리 그래프 | `figure.svg` |
| 표 자료 해석 | 녹는점·끓는점 표로 상태 판단, 실험 결과 표 | `figure.svg`(표를 SVG로) |
| 그림·모형 | 입자 모형, 순환도(A~F), 장치도 | `figure.svg` |
| 실험 상황 | 조건을 바꾼 비교 실험, 변인 통제 | `passageTitle:"실험"`, `passage` |
| 〈보기〉 합답형 | "옳은 것만을 〈보기〉에서 있는 대로 고른 것은?" | `passage`에 ㄱ~ㄹ, 보기는 `"ㄱ, ㄴ"`, `fixedOrder:true` |
| 사례 분류 | 생활 현상 중 종류가 다른 하나 | — |
| 조건 서술형 | "(단, '열에너지'와 '입자 배열'을 모두 사용할 것)" | `answerHint`, 부분 점수 `rubric` |
- **오답 보기 = 실제 오개념.** "고체 입자는 멈춰 있다", "상태가 변하면 질량이 변한다", "녹는점은 양에 따라 변한다"처럼 학생이 진짜로 하는 착각을 쓴다. 터무니없는 보기, 정답만 눈에 띄게 긴 보기 금지. "모두 옳다/정답 없음" 금지.
- 난이도: 하 = 개념 확인 / 중 = 적용·사례 판단·합답형 / 상 = 자료 해석 + 여러 개념 결합, 경계값 함정(예: 녹는점 17℃ 물질의 20℃ 상태).
- 발문은 학교 시험 말투: "~에 대한 설명으로 옳은 것은?", "~만을 〈보기〉에서 있는 대로 고른 것은?", "~을 서술하시오."
- 중학생 수준 어휘. 교육과정 밖 개념 금지.

## SVG 그림 규칙 (`figure.svg`, `refs[].svg`)
- 원문 그림을 베끼지 말고 **새로 그린다.** viewBox 사용, 가로 300~400 정도, `font-family='sans-serif'`.
- 흰 배경 위에 표시되므로 진한 색(#222 등)으로 그린다. 축·눈금·단위·라벨을 정확히.
- 스크립트·이벤트 속성·외부 링크 금지(빌드가 거부). 화살표 marker 등 내부 id는 써도 된다(앱이 자동으로 고유화).
- 그래프 수치는 문항·해설과 정확히 일치해야 한다(내용 검수 대상).

## questions.json 형식
```json
{ "questions": [
  { "id": "u2-Q07-a", "slot": "Q07", "type": "mc", "difficulty": "상", "points": 6, "concept": "가열·냉각 곡선",
    "figure": { "svg": "<svg …>…</svg>", "caption": "고체 물질 X를 가열할 때의 온도 변화" },
    "passageTitle": "(선택) 실험", "passage": "(선택) 제시문 / 〈보기〉\nㄱ. …\nㄴ. …",
    "question": "…옳은 것만을 〈보기〉에서 있는 대로 고른 것은?",
    "choices": ["ㄱ", "ㄷ", "ㄱ, ㄴ", "ㄴ, ㄷ", "ㄱ, ㄴ, ㄷ"], "answer": 3, "fixedOrder": true,
    "explanation": "한두 문장 해설 (연습 모드 즉시 채점)",
    "choiceExplanations": ["…", "…", "…", "…", "…"], "detail": "…", "tip": "…", "refs": [ … ],
    "source": "교과서 p.34" },
  { "id": "u2-Q10-a", "slot": "Q10", "type": "short", "answer": ["끓는점"], "answerHint": "세 글자로 쓰시오.", "commonMistakes": [ … ], … },
  { "id": "u2-S01-a", "slot": "S01", "type": "essay", "answerHint": "(단, …)", "modelAnswer": "…",
    "rubric": [ { "criterion": "…을 씀", "points": 6, "tip": "…" } ], … }
] }
```
- `type`: mc / short / ox / essay. `answer`(mc)는 1부터 시작하는 번호, 복수 정답은 배열(발문에 개수 명시).
- `fixedOrder`가 없는 선택형은 보기가 섞인다 → 해설·팁에 ①~⑤ 금지(빌드가 거부).
- 단답형: 답이 하나로 정해지는 질문만. 인정 답안은 `answer` 배열에 모두.
- 서술형: 채점 기준 점수 합 = 배점, 기준은 체크 가능한 문장.
- 모든 문항에 `source`. 교과서와 자습서가 다르면 교과서를 따르고 해설에 적는다.
- `origin`/`pastExamRef`: 기출 변환 문항에만 쓴다(위 "기출 활용"). 새로 만든 문항에는 넣지 않는다.

## 자체 점검
`python engine/build_library.py --check-unit drafts/<책id>/<단원id>` → `✖` 0개가 될 때까지 고친다. `⚠`(변형 부족, refs 없음 등)도 해소한다.

## 반려 문항 수정
지적된 문항만 고친다. 다른 문항을 바꿔야 하면 이유를 보고한다. 수정 후 다시 빌드 검사.

## 개정 규칙 (2026-11-15)
`docs/내신-적합성-검토와-개정안.md`의 R1~R7을 반영한다. 위의 기존 규칙과 충돌하면 **이 절이 우선**한다.
- **배점 (R1)**: 슬롯의 `points`를 그대로 쓴다. 선택형 3~5점, 단답 3~4점, 서술형 4~8점 범위를 벗어난 설계도는 `exam-designer`에 되돌린다.
- **사실 배분 (R2)**: 출제 전에 blueprint의 슬롯별 `facts`를 확인한다. 자기 슬롯 밖의 정답 근거 사실을 발문·지문·보기에서 **참으로 단언하지 않는다**(오답 보기의 거짓 진술은 허용). 문항을 다 쓰면 슬롯별 정답 사실을 목록으로 만들어 다른 문항의 발문·지문·보기 문장에서 검색해 확인한다.
- **과목별 형식 (R3)**: `exam-designer`의 과목별 형식 표를 따른다. 기후 그래프처럼 정의에 맞춰 직접 만든 자료는 캡션에 '모식도'라고 쓰고, 실제 관측 자료처럼 보이게 하지 않는다.
- **선택지 길이 균형 (R4)**: 정답을 가장 길거나 가장 구체적인 보기로 만들지 않는다. 오답을 정답과 같은 구조·비슷한 길이로 쓴다. 정답 위치는 코드(예: `place(correct, wrongs, pos)`)로 1~5번에 고르게 분산한다. 단원 완성 후 빌드 경고 '정답이 가장 긴 보기 40% 초과'가 없어야 한다.
- **지엽성 (R5)**: 연도·고유명 단답은 단원당 최대 1문항. 교과서가 강조하지 않는 세부 수치·연도는 쓰지 않는다.
- **원문 이설·해석 용어 (R6)**: 같은 사실의 연도·수치가 문서마다 다르면(예: 법흥왕의 불교 공인 527/528년) 문항에서 묻지 않고 notes.md의 '문항에서 다루지 않은 것'에 적는다. 원문에 없는 해석·수사 용어(예: 반어법)는 정답 근거로 쓰지 않는다.
- **서술형 감점 요소 (R7)**: 영작은 철자·시제·어순 오류 감점, 계산·풀이 서술은 단계별 배점, 조건어 누락 시 해당 기준 0점을 기준 문장 또는 `tip`에 명시한다. 허용 가능한 다른 표현(예: new alphabet / new writing system)이 있으면 모범 답안 옆에 적는다.
- **계산·연도는 코드로 검증**: 수학의 계산값, 연표의 연도, 보기의 진위는 스크립트로 단언(assert)하고, 사실은 materials 원문과 정규식으로 대조한 뒤 검수에 넘긴다.
- **도덕 과목**: `docs/도덕-출제-기준.md`를 따른다. 가치 판단(의견) 문항 금지, 오답을 '명백히 나쁜 행동'으로만 구성하지 않기, 서술형은 사례→개념 적용→조건 낱말 구조인지 확인한다.


## 지문 규칙 (2026-11-15, 사용자 지정 — 모든 과목, 특히 국어)
- **특정 작품·글·표·그래프·사례의 내용을 묻는 문항에는 그 지문·자료를 문항에 반드시 넣는다.** 학생이 교과서를 미리 읽지 않았어도 지문만 읽고 풀 수 있어야 한다. 국어는 교과서 원문을 **짧게 그대로 인용**(저작권을 위해 필요한 만큼만, 생략은 `(…)`)하고, 앞뒤 사정이 필요하면 `[앞부분 줄거리]`처럼 한 줄 요약을 붙인다. 인용은 `engine/precheck_unit.py`가 원문 존재를 확인한다.
- 지문 없이 묻는 문항은 **개념·용어·일반 지식 문항**(예: 성장 소설의 특징, 글쓰기 단계의 뜻)이거나, 문항 안에 필요한 정보가 모두 있는 문항이어야 한다. "~에서 '나'가 ~한 까닭은?"처럼 작품 장면을 전제하는 발문은 지문이 없으면 안 된다.
- 서술형도 같다(작품 내용을 쓰게 하면 해당 부분을 제시). 〈보기〉와 작품을 함께 감상하는 문항은 작품 일부를 [가], 〈보기〉를 [나]로 모두 제시한다.
- 같은 작품 지문을 공유하는 문항들 사이에 지문 내용이 겹치는 것은 정상이다(실제 시험도 한 지문으로 여러 문항을 낸다). 다만 한 문항의 **정답 문장이나 서술형 조건 낱말을 다른 문항의 보기·발문이 그대로 알려 주면** 안 된다.

- **과목별 기준(사용자 지시)**: 해당 과목의 `docs/subjects/<과목>.md`를 먼저 읽고 따른다. **가장 먼저 '0. 기출 유형'**(학교 기출에서 나온 시험 구성·난이도 배분·출제 경향·반영 규칙, 사용자 지시 2026-11-15 최우선)을 읽고, 다른 항목·`docs/내신-적합성-검토와-개정안.md`의 권장값과 어긋나면 기출 유형이 이긴다. 그다음 '출제 형식', '지문·자료 규칙', '자주 나온 반려 사유', '다음 단원에서 개선할 것'을 본다.

## 반려 예방 (모든 과목 공통)
- 출제·풀이 작성 전에 `docs/출제-반려-예방.md`를 읽는다(슬롯 간 정답 노출·합답 구성·정답 최장·그림 글자 잘림·쪽수 등 반복 반려 사유와 작업 순서). 검수 전 `python engine/precheck_unit.py <책> <단원> --pages a-b --src 교과서.txt "교사용 교과서.txt"`가 ✖ 0건이어야 한다. 새 반려 사유는 그 문서와 `engine/_precheck_extra.py`, 과목 md 5번에 함께 추가한다.
